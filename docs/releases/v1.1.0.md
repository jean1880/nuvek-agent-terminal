Agent Terminal 1.1.0 brings your own models into the app: a new **Local** agent runs models on your own server, Claude and Codex can run on a local or self-hosted model server instead of their vendor's, and a thread stopped by its usage limit now picks up again once the limit resets.

## Added

- **The Local agent.** A fourth agent, run by Agent Terminal itself, for models on your own server: Ollama, LM Studio, vLLM, llama.cpp server, SGLang, LocalAI, Jan, text-generation-webui, LiteLLM or any OpenAI-compatible server. Add as many servers as you like in Settings → Agents → **Local Model Servers**; each one is its own entry under New Thread With and lists its own models (embedding models are left out). The agent works in the thread's folder with six tools (read, list, search, write, edit, run a command), gated by the same modes as the other agents: Plan only reads, Ask asks before every write and command, Accept edits asks before commands and before writing outside the folder or to a sensitive file. Reading outside the folder or a sensitive file asks in every mode, a search never reads secrets and says what it left out, and files are written whole or not at all, keeping their permissions and owner. Conversations resume where they were.
- **Instructions and MCP tools for the Local agent.** Settings → Agents → **Local Instructions and Tools**: your `AGENTS.md` files (a native one, any global files you name, and those of the thread's folder and its parents, with an optional `CLAUDE.md` fallback), a whole-request context budget, and MCP servers run as local child processes. Each MCP tool is allowed by exact name, declared read-only or not, and given an approval policy; every call shows its server, real tool name and exact (masked) arguments on an approval card. MCP definitions can be imported from a Codex `config.toml`. See [Local instructions and tools](../configuration.md#local-instructions-and-tools).
- **Claude and Codex on a model server.** Under Settings → Agents → **Model Provider**, a Claude or Codex profile can run on Ollama (0.14+), LM Studio (0.4.1+) or a LiteLLM gateway instead of its vendor. One agent can have a cloud profile and a local one side by side. Such a profile never falls back to the vendor: a bad address or a missing key refuses the start. API keys are named by variable, never stored, and kept out of Claude's environment. Terminal tabs of such a profile run on the server too (POSIX shells). See [Claude and Codex on a model server](../configuration.md#claude-and-codex-on-a-model-server).
- **A model picker grouped by server.** The picker shows one group per source, each agent's vendor and every enabled profile on a model server, under its name, kind and address, and says why a group is empty (checking, not reachable, no chat model). Picking a model in another group moves the thread there, continuing from a handoff. The header chip names the server the thread runs on.
- **Continue after a usage limit.** When a thread's turn fails because the agent ran out of quota, the thread waits for the limit to reset, then continues in the same session, restarting the agent if needed. A banner shows when it will continue, with **Don't Continue** and **Continue in …** (switch to another agent and carry on there). It backs off if a continuation is refused, and never continues a thread you stopped. Settings → General → Threads → **Continue When Usage Limits Reset** (on by default).
- **Background task shelf.** Background tasks get a shelf above the composer, stacked with the sub-agent shelf as one card.
- **Sub-agents waiting on you are shown.** A parent thread shows when one of its workers is waiting for an approval, question or form from you.
- **Idle sub-agents are paused, and the number of agent processes is capped.** A delegated worker idle for the idle-suspend time is paused and resumed in the same session by its next instruction. When a new start would pass the process limit, the least recently active idle worker is paused first; with none to pause, the start is refused and says how many are idle.
- **Dialogs close on a press outside them**, as Escape does.
- **About Agent Terminal** and **Keyboard Shortcuts** in the main menu, and an empty-state message when the sidebar has no threads or a search matches none.

## Changed

- Settings: Pause Idle Agents, Continue When Usage Limits Reset and Show Sessions Started Outside Agent Terminal move to a **Threads** group under General, and Text Scale joins Theme under General → Appearance. The Terminal page keeps only the terminal's own settings.
- Starting Directory, Worktree Folder, the diff tool and permission sources are saved only when committed (Enter or focus leaving), never on a half-typed value, and a missing folder is named inline.
- Secondary text (timestamps, placeholders, captions, diff file headers) reaches a 4.5:1 contrast ratio on every bundled theme and on the System theme in light and dark.
- One name per action across menus, tooltips and the shortcuts window; **Stop turn** everywhere a turn is ended; **Show More / Show Less** on every expandable card; header case on titles and buttons; message dialogs close with **Close**.
- The sidebar's duplicate **+** button is gone (use New Thread in the header), paths use `~` throughout, and the model chip no longer cuts a model id short while there is room.
- The terminal's context menu also opens with the Menu key, Shift+F10 or a long press.
- Better screen reader labels for the mode, extra access, MCP rows and the update indicator.
- Hand-offs keep the latest request and a fork's inherited context, say what each tool did, and are cut only when too long.
- The thread store moves to a new schema with stricter ownership keys and indexes; existing threads are upgraded automatically on first start.

## Fixed

- agy 1.4's tool names are recognised in approvals, the delegation gate and cards, and a hook query now covers only the step of its own tool.
- Delegation: a steer is never run twice, late answers and sibling revocations no longer fail paused workers, queued deliveries keep draining after a failure, and a Claude child in Accept edits has its contained edits answered instead of waiting until denied.
- A backgrounded shell launch of an agent (such as `cross-agent codex …`) is listed as that sub-agent.
- Switching agents while a turn is busy continues once, gives carried messages back to the old agent if the switch fails, and asks "Continue in …" for one switch only.
- Turning delegation off during Antigravity's environment review keeps it off.
- The About dialog shows the colour app icon.
- Packaging: the Rust installer used by the build scripts is pinned and checksum-verified, and the scratch build tree is removed when a build exits.

## Upgrade and install

Existing settings and threads are kept. The thread store is upgraded on first start; an older release cannot open it afterwards.

Download the package for your distribution and `SHA256SUMS` from this release, verify the checksum (and, optionally, the build provenance with `gh attestation verify <file> --repo jean1880/nuvek-agent-terminal`), then install it:

| Distribution | Command |
|---|---|
| Debian 13, Ubuntu 24.04 or newer | `sudo apt install ./agent-terminal_1.1.0-1_amd64.deb` |
| Fedora 40 or newer | `sudo dnf install ./agent-terminal-1.1.0-1.x86_64.rpm` |
| Arch Linux | `sudo pacman -U ./agent-terminal-1.1.0-1-x86_64.pkg.tar.zst` |

## Known limitations

- The Local agent cannot take part in cross-agent delegation.
- A model that does not support tool calling still answers in a Local thread, but cannot read or change anything. Some servers need tool calling switched on (vLLM, SGLang, llama.cpp's `--jinja`).
- Claude on a model server can read its own key file: the file keeps the key out of environment listings and away from other users, not away from the agent's own tools.
- Antigravity runs only Google's models; it cannot use a model server.
- The 1.0.0 limitations on agy's hook proof, Codex sub-agents and the pattern-based redactor still apply.
