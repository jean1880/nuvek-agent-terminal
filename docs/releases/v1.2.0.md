Agent Terminal 1.2.0 brings images into the conversation and makes the Local agent a full member of cross-agent delegation: it can now run sub-agents and be one, with your own model tags, cost and GPU headroom guiding which agent gets the work.

## Added

- **Images in the conversation.** Attach a screenshot or any PNG, JPEG, WebP or GIF with the paperclip, by pasting it (`Ctrl+V`; text on the clipboard still pastes as text) or by dropping it anywhere on the thread: up to five per message, shown in a tray in the composer before you send them, then inside your message. Images travel with their message through the queue, steering and retries. Claude, Codex and the Local agent (with a model that reads images) receive them; Antigravity takes text only, so the message stays in the composer and says so. Images are resized to 2048 pixels, stripped of their metadata and kept only on your machine, and are removed a day after no thread uses them. Hand-offs name an image (`[image: name]`), never its contents, and a thread started with an image alone is titled by its file name.
- **Images agents look at and show you.** An image an agent views (a file Codex opens, a screenshot an MCP tool returns, a Claude tool result) appears as thumbnails on that step's card. Local images a reply links to in its markdown, inside the thread's folder, appear under the reply; nothing is ever fetched from the web.
- **An image viewer.** Click any image to see it fitted or at actual size, step through the others, copy it, save it, or open it in your image viewer (through a private copy, so the stored image never changes).
- **`show_image` for sub-agents and parents.** The `agent_terminal` tools gain `show_image`, which shows you up to five image files from the agent's folder, each with a caption, under its card. It needs no delegation and counts as a read, so a planning sub-agent may use it. A file outside the agent's folder, or a sensitive one, is refused with the reason.
- **The Local agent in delegation.** A Local thread can start and direct sub-agents on any agent with the same eight `cross_agent_*` tools, and a Local server can be a sub-agent of any agent. As a sub-agent it works in the task mode and worktree its parent asked for, asks Agent Terminal before every change and command (Accept edits inside its own worktree is answered for it; anything its parent did not allow is refused) and uses none of your Local MCP servers. A model the server says cannot call tools is refused; a requested effort is ignored and the receipt says so. Each Local server joins delegation on its own **Available to Other Agents** switch. See the [delegation guide](../delegation/user-guide.md).
- **Your own model tags.** Settings → Agents → **Model Tags** lists every model of every enabled profile with its tier, tags, best-for note and where they came from, and lets you edit or reset them. The same edits are available from the command line with `agent-terminal tags list | show | set | unset`. Your tags are kept in `model-tags.user.json`, written only by Agent Terminal, and go over the shared tag file and the built-in tags; an entry can be limited to one profile, so the same model on two servers can be tagged differently. See [Model tags](../configuration.md#model-tags).
- **Free to Run.** A Local server marked **Free to Run** (on by default for Ollama, LM Studio and other servers you run yourself; off for LiteLLM and Other) is reported to parents as `cost: free`, and parents are told to prefer it when its tags and tier fit the task.
- **Headroom probe.** A Local server can name a **Headroom Probe**, a command that prints one number (free GPU memory, say), and a **Low Below** threshold. While the reading is under it, delegation reports the server as busy, so work goes to another agent while, for instance, a game holds the GPU. A probe that fails, times out or has not read recently reports `unknown`, never `ok`. The probe runs without a shell, with a minimal environment, a time limit and a cap on its output, and nothing it starts outlives it. Readings are also written to `usage.json` under `local`. See [Local model servers](../configuration.md#local-model-servers-the-local-agent).
- **New Thread in Existing Folder With.** The New menu gains a submenu that asks for a folder and opens a thread there with the agent or Local server you pick.
- **A journal record for every delegated run.** When a sub-agent's run ends, one structured `delegated run ended` record is logged with its agent, profile, requested and effective model, task mode, outcome, duration, token counts and result size; never the task, the result's text, a path or a credential.

## Changed

- **Dangerous permissive mode lends Accept edits to sub-agents.** A thread in Dangerous permissive mode is unattended, so its sub-agents now start in Accept edits (writing inside their own worktrees) instead of Ask. Dangerous permissive mode itself still never passes to a sub-agent.
- An idle thread in Dangerous permissive mode is now paused like any other idle thread.
- A delegation root's new Local settings never stop it while it has sub-agents or the rotation is refused: they apply at a later prompt. Narrowing a root's MCP access still stops it at once, with its sub-agents, and says so.
- Capabilities report each profile's `cost` and each model's `tags_source`.

## Fixed

- **The Local agent's commands can no longer read the model server's key.** The runner removes the key from its environment once read and makes itself non-dumpable before anything else, so the commands it runs cannot read its environment or memory; a runner that cannot do so does not start.
- A thinking model that puts its whole answer in its reasoning no longer leaves a Local turn empty: the agent asks once for the answer as reply text, and otherwise shows the reasoning, marked as such.
- A running delegated worker can be switched to Antigravity.
- The header's agent chip stays on one line.
- Dependencies are updated, clearing RUSTSEC-2026-0433 (`pulldown-cmark`) and RUSTSEC-2026-0462 (`rmcp`). Neither was reachable: Agent Terminal enables no wikilinks and runs MCP servers over stdio only.

## Upgrade and install

Existing settings and threads are kept; this release does not change the thread store.

Download the package for your distribution and `SHA256SUMS` from this release, verify the checksum (and, optionally, the build provenance with `gh attestation verify <file> --repo jean1880/nuvek-agent-terminal`), then install it:

| Distribution | Command |
|---|---|
| Debian 13, Ubuntu 24.04 or newer | `sudo apt install ./agent-terminal_1.2.0-1_amd64.deb` |
| Fedora 40 or newer | `sudo dnf install ./agent-terminal-1.2.0-1.x86_64.rpm` |
| Arch Linux | `sudo pacman -U ./agent-terminal-1.2.0-1-x86_64.pkg.tar.zst` |

## Known limitations

- Antigravity takes text only: a message with images stays in the composer.
- A model server that delegated work runs on receives the task and whatever the agent reads; a gateway such as LiteLLM may forward that to a cloud model, so point delegated work at servers you trust with it.
- The Local agent's key stays readable wherever it came from: a key kept in the profile's environment file, or exported by your shell, can be read there by the agent's commands, which run as you.
- A process that can trace the Local runner (root, or one with `CAP_SYS_PTRACE`) can read its memory, including the server key and its delegation capability.
- A model that does not support tool calling still answers in a Local thread, but cannot read or change anything, and cannot be a sub-agent. Some servers need tool calling switched on (vLLM, SGLang, llama.cpp's `--jinja`).
- Claude on a model server can read its own key file, and Antigravity runs only Google's models.
- The 1.0.0 limitations on agy's hook proof, Codex sub-agents and the pattern-based redactor still apply.
