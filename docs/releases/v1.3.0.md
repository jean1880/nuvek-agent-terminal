Agent Terminal 1.3.0 is about working with more than one answer and finding your way back to it. You can fork into a worktree of its own, ask several agents at once, compare any two threads and keep the one that worked, then commit, review and merge from the diff panel. Threads gain pins, tags, message search, scheduled prompts, a spending history and a context gauge, and the whole app becomes easier to use with a keyboard and a screen reader.

## Added

### Several answers, one choice

- **Fork in an isolated worktree.** **Fork in Isolated Worktree…** in a thread's context menu, or `/fork worktree`, puts the fork on a new `fork/…` branch at the source's commit, in a worktree of its own. The source folder's uncommitted work is copied in, still uncommitted, so the two never edit the same files. A file whose name looks like a secret is never copied. Plain `/fork` still forks in place.
- **Compare threads side by side.** **Compare with…** opens any two threads, including archived ones, side by side. **Compare with Fork…**, `/compare` or the fork toast's **Compare** lines a fork and its source up turn by turn since the fork. In a git repository, a **Changes** tab shows what changed in each folder since then.
- **Keep This One.** This archives the other thread, without deleting it (Undo brings it back), and notes the choice in the thread you kept. It also offers to remove the other thread's worktree, but only when nothing in it is uncommitted and no other thread works there. The branch is always kept.
- **Ask several agents at once.** **Ask Several Agents…** in the composer menu, or `/ask`, sends one prompt to 2–4 agents, models or profiles in parallel. **Compare Group…** shows their replies and diffs side by side. Keeping one archives the rest and carries the chosen answer into your next message. The launch dialog shows each account's cost and headroom first.
- **Scheduled and repeating prompts.** **Schedule…** in the send menu, `/schedule` or `Ctrl+Shift+L` runs a prompt once, daily, weekly or at an interval, in the current thread or in a new thread or worktree. **Scheduled Prompts…** lists upcoming runs; each can be paused, resumed, edited, run now or deleted. A repeating schedule pauses itself after 10 runs without a reply from you, or when a spending warning is reached. Turn all scheduled runs off in Settings → General → Threads.

### The diff panel

- **Commit from the diff panel.** Tick the files or individual hunks you want, then **Commit…**. It runs through your own git, with your hooks and signing, after showing you the exact commands. Whatever you had staged elsewhere stays staged.
- **Review a diff.** Select lines and **Comment** (`Ctrl+Alt+M`), in the panel or on a file change in the thread. **Send Review** sends every comment to the agent as one message, with paths, lines and the quoted code. Each comment's lines are checked against the file first, and the message says which ones have moved or gone. Unsent comments are kept with the thread.
- **Merge a worktree back.** **Merge into ‹base›…** merges, squashes or rebases a worktree's branch into its base. It shows the exact commands first and refuses anything half-done. When conflicts or uncommitted changes block it, it offers **Ask Agent to Bring in ‹base›** or **Commit First…**. A merge that stops part-way is undone, and the branch is always kept. A delegated worker in its own worktree offers **Merge Branch…** too. Pick the starting method with `default_merge_method`.
- **Open in your editor.** Configure an editor and a file opens at its first changed line. Ctrl+click opens any line of a diff. A read's card and links such as `src/a.rs:12` in a reply open there too. A file outside the thread's folder is asked about every time.

### Threads and the sidebar

- **Pins and tags.** **Pin to Top** (`Ctrl+Shift+P`) puts threads in a **Pinned** section, in the order you choose (`Alt+Shift+Up`/`Down`). **Tags…** gives a thread up to eight tags, each with an optional colour. Click a tag chip, or type `#tag` in the search, to filter the sidebar.
- **Search inside threads.** **Also Search Messages**, beside the sidebar's search, adds an **In Messages** section with up to 50 matches. Opening one takes you to the message itself. The index holds your messages, the replies and tool titles, redacted. It never holds a tool's output or the model's reasoning. Threads from earlier versions are indexed in the background after start-up.
- **Spending history.** **Spending…** in the header menu shows what completed turns cost, by day, week or month. Totals can be grouped by folder, agent, profile or model. Each turn records how it was paid for, so metered spending and a plan's list price are never added together. A turn that reported no cost says "Not reported", never $0. Deleted threads still count. An optional daily or monthly warning (Settings → General → Spending) counts real money only.
- **Context left.** The header gauge shows how much of the context window remains, amber at the warning point and red at 90%. Click it to compact, continue in a new thread or see the `/context` breakdown. The first time a thread passes the warning point (75% by default; 60, 75, 90 or never), a note above the message box offers both. A Local thread's gauge is an estimate against its profile's context budget.
- **Saved prompts.** Prompts you repeat are listed after `/` in the composer. `{file}`, `{branch}`, `{selection}` and `{folder}` are filled in from the thread, and nothing is sent until you press Enter. Manage them in Settings → General → Saved Prompts, optionally limited to one folder.
- **Export a thread** as Markdown or JSON from its context menu. Tool output can be included or left out, and so can reasoning (off by default). Images appear only by name, known secret patterns are masked, and the file is readable only by you.

### Terminals and other machines

- **Send terminal text to a thread.** Right-click a drawer or a terminal page and choose **Send Selection** or **Send Last Output to Thread**. The text is added to a thread's draft as a labelled, redacted, size-capped block. Nothing is sent until you send it.
- **Remote machines.** List the machines you reach with `ssh` in Settings → General → Remote Machines. **New Terminal Thread on Another Machine…** opens a terminal page in a folder there. **New Thread on Another Machine…** runs Claude or Codex there as a chat thread. Both use your own `ssh` and configuration, with forwarding of every kind switched off, and nothing connects until you ask.

### Appearance and accessibility

- **Light themes.** Agent Terminal Light, Solarized Light, Gruvbox Light, One Light and GitHub Light. **Match Desktop: Light and Dark** switches between a light and a dark scheme of your choice as your desktop does.
- **Screen reader announcements.** A finished or failed turn, an approval or question waiting, and errors are read out by Orca or another screen reader, without repeating a desktop notification.
- **F6 and Shift+F6** move between the thread list, the transcript, the message box, the terminal and the Changes panel. From a terminal, use Ctrl+F6, since its program keeps F6. Each region is a named landmark, and every transcript row is named by its author.
- **Text Scale** now sizes all the app's text, live, with Ctrl+= and Ctrl+-.

### Delegation

- **MCP tools for Claude sub-agents.** A Claude profile's optional `child_mcp_servers` grants its delegated Claude children explicit stdio MCP servers, each with an exact list of tool names. Every call is checked against that list, whatever the server advertises. See [Profiles](../configuration.md#profiles).

## Changed

- **Antigravity runs in dangerous permissive mode only.** Headless agy has no working way to ask before it acts, so every agy thread and sub-agent now runs with `--dangerously-skip-permissions`. It runs commands and edits files without asking, and its mode picker is locked on **Dangerous permissive (forced)**. The approval hook is no longer used. If you added the `agent-terminal-approval` entry to `~/.gemini/config/hooks.json`, you can remove it.
- Every bundled colour scheme's outlines, accent, state colours and focus ring now have at least 3:1 contrast on every surface.
- Delegation ranks an agent's load by its least-used quota group, so an agent with one exhausted group but another free is no longer passed over.
- Agents are kept running rather than stopped or narrowed: a choice made while a root was stopped is kept when it starts again.

## Fixed

- Claude turns now report their own cost, not the process's running total.
- agy's context window is shown as unknown instead of a guessed 1M.
- The image an agy file read gave its model is shown on its card.
- agy's usage no longer shows a reset in 1970 for a quota group it has not used, and a limit wait no longer treats that group as already reset.
- Solarized Dark's body text reads on raised surfaces.
- Every button has an accessible name and size, checked across the whole window in CI.
- An agy sub-agent starts unbound, instead of failing, when its workspace withholds delegation.
- Dependencies are updated. RUSTSEC-2026-0543 ("chrono is unmaintained") is acknowledged: chrono comes in through `rmcp` and `schemars`.

## Upgrade and install

Existing settings and threads are kept. The thread store is upgraded to schema 11 the first time 1.3.0 opens it; an earlier version cannot open it afterwards. Threads from earlier versions are indexed for message search in the background after start-up.

Download the package for your distribution and `SHA256SUMS` from this release, verify the checksum (and, optionally, the build provenance with `gh attestation verify <file> --repo jean1880/nuvek-agent-terminal`), then install it:

| Distribution | Command |
|---|---|
| Debian 13, Ubuntu 24.04 or newer | `sudo apt install ./agent-terminal_1.3.0-1_amd64.deb` |
| Fedora 40 or newer | `sudo dnf install ./agent-terminal-1.3.0-1.x86_64.rpm` |
| Arch Linux | `sudo pacman -U ./agent-terminal-1.3.0-1-x86_64.pkg.tar.zst` |

## Known limitations

- Antigravity acts without asking, and a delegated agy sub-agent's declared limits are not enforced; only its `cross_agent_*` calls are checked.
- A thread on another machine is Claude or Codex only, and works in a reduced form: approvals offer Allow once and Deny only, and it has no checkpoints, diff panel, undo, worktrees, hand-off briefs, sub-agents or usage-limit continuation. Stop interrupts the agent, but a tool it started there may keep running.
- Claude's extra usage is shown for reference only and never counted toward a spending warning: its unit is not confirmed.
- A secret in a format the redactor does not know may remain in an export or a review.
- The 1.2.0 limitations on images with Antigravity, Local model servers and their keys, and the 1.0.0 limitations on Codex sub-agents and the pattern-based redactor, still apply.
